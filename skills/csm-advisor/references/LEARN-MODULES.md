# Selecting Microsoft Learn Resources (Stage 3)

Goal: after the path(s) are chosen (see [PATH-SELECTION.md](PATH-SELECTION.md)), hand-pick the
Microsoft Learn content that the confirmed signals and selected path(s) justify, and have the user
approve it before the skilling plan is written. This stage produces a chat checkpoint, not a
document.

## Rules

- Use Microsoft Learn (learn.microsoft.com) as the primary source for self-directed learning links.
  Search with whatever Learn, documentation, or web-search tool Cowork provides.
- **Never invent** module titles, learning paths, links, course codes, availability, or durations.
  Copy links from search results rather than from memory. Leave level and duration blank if the
  result does not show them.
- **Verify every link** supports the identified skill and the intended audience: the module exists,
  the link resolves from the search result, and its description matches the skill need.
- If no tool can reach Microsoft Learn, say so once and ask the user to provide module names or
  links. Do not fall back to guessing.
- Prefer a short, well-matched list over an exhaustive one. Each module must trace to a confirmed
  signal and to a selected path. Prefer learning paths for broad needs and single modules for narrow
  ones.
- Skip content the signals show an audience already completed.
- Do not promise instructor-led course availability, dates, delivery capacity, or cloud support;
  list any such item as "requires MTT validation".

## How to search

1. List the skill needs from the Signals Summary, grouped by audience and by selected path.
2. For each need, search Learn with the product/technology plus the skill (for example the product
   name with "get started", "administer", "governance", "agents", "prompting").
3. Pick the best match(es); capture title, link, level, duration (if shown), and why it fits.
4. Note any need with no good match as an **open gap** instead of padding the list.

## Shortlist format (chat)

| # | Module / learning path | Link | Level | Duration | Signal / path addressed | Intended audiences |
|---|------------------------|------|-------|----------|-------------------------|--------------------|
| 1 | <title> | <Learn URL> | <level or blank> | <if shown> | <signal; path> | <Leaders / Champions / Advocates / End Users / ...> |

Then add:

- **Open gaps:** needs with no matching Learn content.
- **Assumed prerequisite skills per audience** (at least Leaders, Champions, Advocates, End Users),
  inferred from the signals - state them as assumptions so the user can correct them.
- **Instructor-led or other non-Learn items** that would need MTT validation.

Finish with one question: approve the path(s) and list, or what to add, remove, or replace.
Re-present after each edit. Only move to Stage 4 after approval.
