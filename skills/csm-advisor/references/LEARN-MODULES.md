# Stage 3 - Selecting Microsoft Learn Modules

Goal: hand-pick the Microsoft Learn content that the approved signals actually justify, and have the
user approve it before any skilling path is written. This stage produces a chat shortlist, not a
document.

## Rules

- Use only **real** content found on Microsoft Learn (learn.microsoft.com). Search with whatever
  Learn, documentation, or web-search tool Cowork provides. Never invent module titles, learning
  paths, durations, or URLs, and do not rely on memory for links - copy them from search results.
- If no tool can reach Microsoft Learn, say so once and ask the user to provide module names or
  links. Do not fall back to guessing.
- Verify each pick: the module exists, the link resolves from the search result, and its description
  matches the skilling need.
- Prefer a short, well-matched list over an exhaustive one. Each module must trace to at least one
  approved signal. Prefer learning paths for broad needs and single modules for narrow ones.
- Note the level (beginner / intermediate / advanced) and approximate duration if the result shows
  them; leave them blank rather than guessing.
- Skip modules the signals show people have already completed (prior training).

## How to search

1. List the approved skilling needs from the Signals Summary (one per row of work).
2. For each need, search Learn with the product/technology name plus the skill (e.g. the tool name
   and "get started", "administer", "governance", "adoption").
3. Pick the best match(es); capture title, link, level, duration, and why it fits.
4. Note any need with no good match as an **open gap** instead of padding the list.

## Shortlist format (chat)

Present a compact table:

| # | Module / learning path | Link | Level | Duration | Signal addressed | Intended groups |
|---|------------------------|------|-------|----------|------------------|-----------------|
| 1 | <title> | <Learn URL> | <level> | <approx.> | <signal> | <Leaders / Champions / Advocates / End Users> |

Then add:

- **Open gaps:** needs with no matching Learn content.
- **Assumed prerequisite skills per group** (Leaders, Champions, Advocates, End Users), inferred
  from the signals - state them as assumptions so the user can correct them.

Finish with one question: approve the list, or what to add, remove, or replace. Re-present the
updated table after each edit. Only move to Stage 4 after approval.
