# mtt-esiadmin-lookup — data model

**Purpose:** The esiadmin (Dataverse) tables, fields, lookups and IDs this resolver reads — including the A–F field-group codes the Procedure references.
**Loaded by:** `mtt-esiadmin-lookup` on demand (see SKILL.md → Additional resources)

## Access & querying notes

- **Access-restricted reference tables (HTTP 403).** `esi_labseries` and `esi_course` return **403 on read** for the trainer's connection even though their metadata (schema) is visible. Do **not** treat 403 as fatal: skip that enrichment, fall back to the readable operational tables (`msdyn_incidenttypes` catalog master + `msdyn_workorders`), and tell the user the value needs a read-access grant on those tables from the DynaMight owner. Catalog-level lab status (`esi_labseries`) and the `esi_course` LearnUID→Learn bridge are gated on this — surface them only when readable, otherwise report the field as *unavailable* (not absent/false).
- **Dataverse-MCP `read_query` select gotcha.** Selecting a lookup's denormalized `…name` string field (e.g. `esi_catalogitemsolutionareaname`) or a picklist/boolean virtual `…name` field (e.g. `esi_catalogitemtypename`, `esi_isattindicatorname`) returns **HTTP 400**. Select the **base** field instead — the lookup `_x_value` (e.g. `_esi_catalogitemsolutionarea_value`) or the raw picklist/boolean (`esi_catalogitemtype`, `esi_isattindicator`) — each returns its label in an `@…FormattedValue`. A `startswith` filter combined with `orderby` can also 400; prefer an `eq` filter or drop the `orderby`.
